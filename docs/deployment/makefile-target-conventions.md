# Makefile Target Naming Conventions

Source of truth for how Make targets are named and where they live.
Enforced by `make lint-makefile` (`scripts/lint-makefile-conventions.sh`).

## File layout

```
Makefile           thin loader (.DEFAULT_GOAL=help, includes mk/*)
mk/
  common.mk        vars, exports, generic helm-* macros
  build.mk         build / docker / images / workers / clean
  identity.mk      Keycloak per-cloud install / upgrade / template
  tier-helm.mk     helm_upgrade_tier macro + database / observability / foundation
  dispatch.mk      `make deploy CLOUD=...` + help-<cloud>
  cloud/
    local.mk       deploy-local + local-cluster wrappers
    aks.mk         deploy-all-tiers-aks + AKS wrappers + provisioning
    gke.mk         deploy-gke + GKE wrappers + provisioning
    eks.mk         deploy-eks + EKS wrappers + provisioning
```

- A target named `<cloud>-foo` MUST live in `mk/cloud/<cloud>.mk`.
- A target in `mk/cloud/<cloud>.mk` that is not on the cross-cutting
  tier surface (Layers 2 / 3 / 6) MUST start with `<cloud>-`.

## Layers

Every target falls in exactly one layer:

| # | Pattern | File | Example |
| --- | --- | --- | --- |
| [1](#layer-1) build / util          | `<verb>-<noun>`                              | `mk/{build,common,tier-helm}.mk`                          | `images-build`, `install-gateway-api`, `clean` |
| [2](#layer-2) tier helm wrapper     | `helm-<tier>-upgrade-<cloud>`                | `mk/cloud/<cloud>.mk`                                     | `helm-platform-upgrade-aks`, `helm-llm-gateway-upgrade-eks` |
| [3](#layer-3) per-cloud orchestrator | `deploy-all-tiers-<cloud>`                  | `mk/cloud/<cloud>.mk`                                     | `deploy-all-tiers-aks`, `deploy-all-tiers-eks` |
| [4](#layer-4) dispatch facade       | `make deploy CLOUD=<cloud>`                  | `mk/dispatch.mk`                                          | routes to `deploy-all-tiers-<cloud>` |
| [5](#layer-5) cloud-side helper     | `<cloud>-<verb>-<noun>`                      | `mk/cloud/<cloud>.mk` (or `mk/identity.mk` for Keycloak)  | `aks-keycloak-provision`, `gke-ensure-storage-ready`, `eks-bootstrap-fresh` |
| [6](#layer-6) identity install      | `helm-identity-<verb>-<cloud>`, `<verb>` ∈ `{install, upgrade, template}` | `mk/identity.mk`             | `helm-identity-install-aks`, `helm-identity-install-eks` |
| [7](#layer-7) per-cloud help filter | `help-<cloud>`                               | `mk/dispatch.mk`                                          | `help-aks`, `help-eks` |

`<tier>` ∈ `{platform, llm-gateway, services, console, workers}`. The
`database`, `identity`, and `observability` tiers are cross-cutting and
use their own targets — `helm-database-upgrade`,
`helm-identity-*-<cloud>` (Layer 6), `helm-observability-upgrade` —
rather than the Layer 2 pattern.

### Layer 1

Cloud-agnostic build / util / generic helm helpers. Verb leads noun
(`bucket-provision` ✓, `bucket-default-shared-provision` ✗).

### Layer 2

1–3-line wrapper calling `$(call helm_upgrade_tier,<tier>,...)`. If a
wrapper grows past that, add the missing parameter to `helm_upgrade_tier`
rather than inlining the body.

### Layer 3

`deploy-all-tiers-<cloud>` invokes every Layer 2 wrapper in tier order
plus any Layer 5 prep. `deploy-local` is the legacy local-cluster
orchestrator name; new clouds use the canonical pattern.

### Layer 4

`make deploy CLOUD=<cloud>` routes to `deploy-all-tiers-<cloud>` via
`VALID_CLOUDS` (today: `local aks gke eks`). A thin `deploy-<cloud>`
pre-wrapper may exist for setup that must happen before the orchestrator
runs — e.g. `KEYCLOAK_HOSTNAME` derivation on GKE and EKS.

### Layer 5

Cloud-side provisioning helpers (outside Kubernetes). The cloud token is
always the **cluster name** (`aks`, `gke`, `eks`, `local`) — never the
cloud-platform name (`azure`, `gcp`, `aws`) or IdP-broker name (`entra`,
`oidc`). Cloud is always a prefix.

Forbidden:

- `provision-foo-aks` — cloud-as-suffix → `aks-provision-foo`.
- `keycloak-aks-entra-register` — cloud-in-middle → `aks-keycloak-entra-register`.
- `keycloak-azure-provision` — platform name → `aks-keycloak-provision`.
- Globally-named targets that are actually cloud-specific (e.g. an
  AKS-only chart install hiding under `helm-*` in `mk/tier-helm.mk`
  instead of `aks-*` in `mk/cloud/aks.mk`).

### Layer 6

Keycloak install bodies legitimately differ per cloud (WI + SPC on AKS,
productionMode + sed-rewrite on GKE, chart-rendered + node IAM on EKS,
chart-rendered on local), so they do NOT collapse into
`helm_upgrade_tier`.

### Layer 7

`help-<cloud>` is generated by `awk` over `$(MAKEFILE_LIST)` using this
canonical regex:

```
^(
  helm-[a-z-]+-upgrade-<cloud>      |  # Layer 2
  helm-tier-template-<cloud>        |  # Layer 2 smoke test
  helm-identity-install-<cloud>     |  # Layer 6
  helm-identity-upgrade-<cloud>     |  # Layer 6
  helm-identity-template-<cloud>    |  # Layer 6
  deploy-all-tiers-<cloud>          |  # Layer 3
  <cloud>-[a-z-]+                      # Layer 5 catchall
):.*##
```

The `<cloud>-[a-z-]+` catchall is what keeps the regex stable — every
Layer 5 helper appears automatically without anyone editing it. Legacy
local exceptions are listed by name (`deploy-local-bootstrap-fresh`,
`undeploy-local`, `load-images-local`,
`ensure-local-shared-default-bucket`,
`purge-local-shared-default-bucket`); new clouds must NOT add any.

## Enforcement

`make lint-makefile` runs `scripts/lint-makefile-conventions.sh` and
exits non-zero on the first violation with an actionable message. Wire
into CI with `- run: make lint-makefile`.

| Rule | Description |
| --- | --- |
| **R1** (planned) | Each target with a doc string lives in the file matching its layer |
| **R2**           | Non-cross-cutting targets in `mk/cloud/<cloud>.mk` MUST start with `<cloud>-` |
| **R3**           | No platform name (`azure` / `gcp` / `aws`) where a cluster name (`aks` / `gke` / `eks`) applies |
| **R4**           | No cloud-as-suffix — cloud is always a prefix |
| **R5**           | Every Layer 2 wrapper calls `helm_upgrade_tier` (no inline bodies) |
| **R6**           | `help-<cloud>` regex includes the `<cloud>-[a-z-]+` catchall |
